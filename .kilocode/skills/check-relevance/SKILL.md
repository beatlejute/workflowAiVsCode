# Проверка актуальности тикета (Check Relevance)

> **ОБЯЗАТЕЛЬНО:** Последние строки твоего ответа ВСЕГДА должны быть блоком `---RESULT---`.
> Без этого блока пайплайн не распознает статус и задача перейдёт на execute-task по умолчанию.
> **Fail-safe:** при любых сомнениях возвращай `relevant` — лучше выполнить лишний раз, чем пропустить нужную задачу.

Этот skill проверяет актуальность тикета перед его выполнением.

## Когда использовать

- Тикет перемещён из `ready/` в `in-progress/`
- До вызова `execute-task`
- Для предотвращения дублирования работы

## Шаги проверки

### 1. Прочитать тикет

ID тикета передаётся в промпте как `ticket_id` в секции Context.

```
Путь: .workflow/tickets/in-progress/{TICKET-ID}.md
```

Извлечь:
- `parent_plan` — ссылка на родительский план
- `context.files` — файлы-артефакты, которые должны быть созданы
- Definition of Done (DoD) — критерии готовности
- `dependencies` — зависимости от других тикетов

### 2. Проверить родительский план

Прочитать файл плана из `parent_plan`.

Если план имеет статус `cancelled` или `archived` → тикет **нерелевантен**.

Если план активен (`in-progress`, `active`) или файл не найден → продолжить проверку.

### 3. Проверить выполнение DoD

Быстрая проверка: созданы ли уже ключевые артефакты?

Для каждого пункта DoD типа `file_exists` (файл должен существовать):
- Проверь существует ли файл уже
- Если **все** файловые артефакты уже созданы → возможно задача уже выполнена

**Важно:** наличие файлов — слабый сигнал. Только если артефакты присутствуют И план активен AND нет признаков повторного выполнения → считать нерелевантным.

### 4. Проверить признаки выполнения

Проверить тикет на наличие заполненной секции результата:

- Есть ли секция `## Результат выполнения` или `## Result` с реальным содержимым?
- Есть ли в `## Ревью` запись со статусом `✅ passed`?

Если секция результата заполнена **И** ревью пройдено → тикет **нерелевантен** (уже выполнен).

### 5. Сформулировать вердикт

**Нерелевантен** (`irrelevant`) — если выполнено ХОТЯ БЫ ОДНО из условий:
- Родительский план отменён (`cancelled`) или архивирован (`archived`)
- Тикет уже имеет ревью со статусом `passed`
- Все артефакты DoD уже созданы И тикет содержит заполненный Result

**Актуален** (`relevant`) — во всех остальных случаях, включая:
- Неясность или ошибки при чтении файлов
- Частичное выполнение
- Отсутствие явных признаков завершения

### 6. Вывести структурированный результат

> **КРИТИЧНО**: `status` принимает ТОЛЬКО два значения: `relevant` или `irrelevant`.
> При любых сомнениях → `relevant`.

Если задача **актуальна**:

```
---RESULT---
status: relevant
---RESULT---
```

Если задача **нерелевантна** (уверенно):

```
---RESULT---
status: irrelevant
reason: "Краткое объяснение: план отменён / задача уже выполнена / артефакты присутствуют"
---RESULT---
```

## Алгоритм проверки

```
1. Прочитать тикет из in-progress/{ticket_id}.md
   - Если файл не найден → status: relevant (fail-safe)

2. Проверить parent_plan:
   - Если план cancelled/archived → status: irrelevant
   - Если план активен или файл не найден → продолжить

3. Проверить ревью в тикете:
   - Если есть запись "passed" → status: irrelevant

4. Проверить артефакты DoD:
   - Если все file_exists артефакты существуют И есть заполненный Result → status: irrelevant

5. Default → status: relevant
```

## Интеграция с пайплайном

В пайплайне стейдж `check-relevance` стоит между `move-to-in-progress` и `execute-task`:

1. `move-to-in-progress` перемещает тикет в `in-progress/`
2. `check-relevance` проверяет актуальность
3. По `status` определяется goto-переход:
   - `relevant` → `execute-task` (выполнить задачу)
   - `irrelevant` → `move-ticket` с `target: done` (пропустить, закрыть)
   - `default` → `execute-task` (fail-safe, выполнить)

## Связанные skills

- `execute-task` — выполнение задачи (следует за этим skill при relevant)
- `review-result` — проверка результата после выполнения
